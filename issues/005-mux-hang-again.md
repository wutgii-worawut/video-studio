# 005 · เรนเดอร์ค้างขั้นรวมเสียงอีกรอบ (มี -nostdin แล้วก็ยังค้าง)

- วันที่: 2026-10-10
- tags: render, ffmpeg, audio
- project: sword-of-coming-s3
- ref: 003 (อาการเดียวกัน), 001

## ปัญหา
`node render.mjs sword-of-coming-s3 video` รันเป็น background task (`… 2>&1 | tail -6`) รอบภาพเสร็จแล้ว (`.video-only.mp4` 3180 เฟรม 106 วิ ครบ) แต่ ffmpeg รอบรวมเสียงกิน CPU ค้างกว่า 5 นาที (CPU time 5:25) ไฟล์ mp4 ไม่มี moov atom

## สาเหตุ (ยังไม่รู้)
- ข้อ 003 ที่บอกว่า "น่าจะ" เป็นเรื่อง stdin **ไม่ใช่สาเหตุ** เพราะคำสั่งที่ค้างมี `-nostdin` และ stdio ignore อยู่แล้ว
- คำสั่ง ffmpeg เดียวกันทุกตัวอักษร (ดึงจาก Win32_Process CommandLine):
  - รันเองจาก bash: เสร็จเร็ว
  - รันจากสคริปต์ node ด้วย `execFileSync` และ stdio แบบเดียวกับ render.mjs ผ่าน `| tail`: เสร็จใน 1.5 วิ
  → ค้างเฉพาะตอนต่อท้ายการเรนเดอร์ยาวใน render.mjs
- ข้อต่างที่เหลือ: ตอนรวมเสียง Chrome ทุกตัวยังเปิดอยู่ (`browser.close()` อยู่หลังรวมเสียง) และ ffmpeg รอบภาพเพิ่งปิด ยังไม่ได้พิสูจน์ว่าเป็นตัวไหน

## วิธีแก้ที่ได้ผล
- ตอนนั้น (เหมือน 003):
  - เก็บ command line ของ ffmpeg ที่ค้าง
  - หยุด background task ด้วย TaskStop ซึ่งปิด ffmpeg ที่ค้างไปด้วย
  - รันคำสั่งเดิมเองออกไปเป็นไฟล์ใหม่ แล้ววางแทน `<project>.mp4`
  - ตรวจด้วย ffprobe ได้ 1080x1920, 30fps, 3180 เฟรม มีเสียง
- ถาวร: ยังไม่ได้แก้ `render.mjs` ทางที่จะลองต่อ:
  - (ก) ปิด Chrome ก่อนรวมเสียง
  - (ข) แยกรอบรวมเสียงเป็นคำสั่งของมันเอง
